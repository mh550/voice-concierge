## Fake LLM design (C1-03), read from `agents/llm/llm.py`

Source: `.venv/lib/python3.12/site-packages/livekit/agents/llm/llm.py`. The fake implements `LLMStream._run` and
emits `ChatChunk`s carrying `ChoiceDelta` and `CompletionUsage`, exactly as declared there. The real shapes (1.8.8):

- `CompletionUsage(BaseModel)` (llm.py:34): `completion_tokens: int`, `prompt_tokens: int`, `prompt_cached_tokens:
  int = 0`, `cache_creation_tokens`, `cache_read_tokens`, `reasoning_tokens` (all `= 0`), `total_tokens: int`,
  `service_tier: str | None = None`. The required ones are `completion_tokens`, `prompt_tokens` and `total_tokens`.
- `FunctionToolCall(BaseModel)` (llm.py:59): `type: Literal["function"] = "function"`, `name: str`, `arguments: str`
  (a JSON string), `call_id: str`, `extra: dict | None = None`.
- `ChoiceDelta(BaseModel)` (llm.py:76): `role: ChatRole | None`, `content: str | None`, `tool_calls:
  list[FunctionToolCall] = []`, `extra`.
- `ChatChunk(BaseModel)` (llm.py:84): `id: str`, `delta: ChoiceDelta | None`, `usage: CompletionUsage | None`.
  `has_response()` is true when the delta has content or tool calls (that starts the TTFT clock).
- `LLM` (llm.py:111) is an `ABC` and an `rtc.EventEmitter` over `"metrics_collected" | "error"`. The abstract
  `chat(*, chat_ctx, tools=None, conn_options=DEFAULT_API_CONNECT_OPTIONS, parallel_tool_calls=NOT_GIVEN,
  tool_choice=NOT_GIVEN, extra_kwargs=NOT_GIVEN) -> LLMStream`. `model` and `provider` are properties that default to
  `"unknown"`. Override them (`"fake"`, `"fake"`) so `LLMMetrics.metadata` is labelled.
- `LLMStream.__init__(llm, *, chat_ctx, tools, conn_options)` (llm.py:239) starts two tasks at construction: the main
  task (which calls `_run()` with retries) and `_metrics_monitor_task`. So a stream must be built inside a running
  event loop (pytest-asyncio's `asyncio_mode = "auto"` covers the tests). `_run()` is the single abstract method. It
  pushes chunks with `self._event_ch.send_nowait(ChatChunk(...))`.
- `_metrics_monitor_task` (llm.py:397) reads every chunk, keeps the last `usage`, and at the end builds
  `LLMMetrics(prompt_tokens=usage.prompt_tokens, prompt_cached_tokens=usage.prompt_cached_tokens, …)` and calls
  `self._llm.emit("metrics_collected", metrics)` (llm.py:487). **So the fake gets metrics emission for free** by
  putting a `CompletionUsage` on its last chunk. It must not emit metrics itself. It emits nothing when no chunk
  was sent.
- `LLMStream.collect()` (llm.py:545) returns `CollectedResponse(text="".join(contents).strip(), tool_calls=[…],
  usage=…)`.

Design:

```python
class FakeResponse(BaseModel):          # one scripted reply
    text: str | None = None              # spoken text, or
    tool_call: FakeToolCall | None = None   # name + arguments (dict, serialized to JSON for FunctionToolCall)
    prompt_tokens: int = 0
    prompt_cached_tokens: int = 0
    completion_tokens: int = 0
    chunk_size: int = 8                  # text is split into chunks of this many characters

class FakeLLM(llm.LLM):
    def __init__(self, script: Sequence[FakeResponse | str]) -> None   # str = text reply
    calls: list[FakeLLMCall]             # chat_ctx (a copy), tools, tool_choice per chat() call
    def chat(self, *, chat_ctx, tools=None, conn_options=..., parallel_tool_calls=NOT_GIVEN,
             tool_choice=NOT_GIVEN, extra_kwargs=NOT_GIVEN) -> FakeLLMStream

class FakeLLMStream(llm.LLMStream):
    async def _run(self) -> None:
        # chunk 0: ChatChunk(id=req_id, delta=ChoiceDelta(role="assistant", content=piece))
        # … one chunk per piece of text, or one chunk with tool_calls=[FunctionToolCall(name, arguments, call_id)]
        # last chunk: ChatChunk(id=req_id, usage=CompletionUsage(completion_tokens, prompt_tokens,
        #                       prompt_cached_tokens, total_tokens=prompt+completion))
```

- The script is consumed in order. Running past its end raises a clear `AssertionError` (a test asked for more
  turns than it scripted), not an empty reply.
- `calls` records `chat_ctx.copy()`, so later mutation by the session can't rewrite what a test inspects. That's
  what the prefix-stability test in C1-04 compares.
- `FakeLLM` mirrors the real classes. It doesn't subclass the openai plugin or touch the network, and it sets no
  `_prewarm_impl` (`AgentSession` calls `prewarm()`, which is a no-op on the base class).

## Turn-detection choice (D7 *default*, see `docs/decisions.md`)

**VAD only, via silero.** The session is built with `vad=silero.VAD.load()` (loaded once in the worker's prewarm/setup
hook, as the LiveKit examples do) and `turn_handling={"turn_detection": "vad"}`.

What the 1.8.8 source says (this differs from the run's starting assumption that the turn detector needs a download):

- `AgentSession.__init__` (voice/agent_session.py:576) defaults `turn_detection` to `inference.TurnDetector()`
  and `vad` to `inference.VAD(model="silero")` (:642). So VAD-only must be **explicit**; omitting the key gets the
  model-based detector.
- `inference.TurnDetector()` (inference/eot/detector.py:34) resolves to the **local** `turn-detector-v1-mini`
  unless the worker is hosted on LiveKit Cloud or in dev mode, where it's the cloud `v1` (with keys) and falls back
  to local without them. The local model ships inside the `livekit-local-inference` wheel's native library (34 MB;
  `init_eot()` loads about 108 MB). **There's no `download-files` step and no network at construction.** I checked
  offline: `inference.TurnDetector().model == "turn-detector-v1-mini"` with no LiveKit env.
- `turn_handling.get("turn_detection", inference.TurnDetector())` builds a `TurnDetector()` as the default argument
  even when we pass `"vad"`. That's harmless (no I/O, as above), but tests that construct `AgentSession` pay for it.
- Silero (`livekit.plugins.silero.VAD.load()`) loads its ONNX model from the wheel's `resources/` with no download.

Why VAD only, for now: it's the simplest, most predictable mode for the offline suite and the first morning test.
The model-based detector is the documented alternative, and it's a one-line change in `concierge/worker.py`
(`turn_detection` key). The question for Michael is in D7.

## C1-03 as built

- `Settings` is a `pydantic_settings.BaseSettings` (new dependency `pydantic-settings>=2,<3`, 2.16.0 installed). It
  reads only `os.environ` (no `env_file`, no `secrets_dir`), so it never touches a dotenv file. `off_file` and
  `db_path` are expanded with `expanduser()`. `db_path` defaults to `~/.local/share/voice-concierge/concierge.db`
  (outside the repo, so visitor data can't be committed). `speech=deepgram` requires a `deepgram/` stt id.

  `build_stt`/`build_tts` construct `inference.STT(model=)`/`inference.TTS(model=)` or

## C1-04 as built

- `build_instructions(pack, memory_block)` joins static, pack (verbatim, so `out.index(load_pack())` works) and the
  memory block with blank lines. `None` or a blank string means a new visitor (no section). The block arrives **already
  rendered** under `MEMORY_HEADER` (C3-02's `render_memory_block` starts with it); `build_instructions` only places it
  and raises `ValueError` past `MEMORY_BLOCK_MAX_CHARS = 1500`.
- `STATIC_INSTRUCTIONS` describes the memory section without quoting `MEMORY_HEADER`, because C3-02 asserts a new
  visitor's prompt contains no header. It ends with `Knowledge pack (the only source of facts about Michael):`. Talk
  about the visitor and their earlier visits is explicitly on-topic, so the off-topic rule does not decline memory
  turns. Budget now: static 1,263 chars; static + pack estimates 2,554 tokens of 3,000, leaving ~1,550 chars for
  C3-03's name rule and C4's tool guidance.
- In 1.8.8 the instructions reach the LLM as `chat_ctx.items[0]`, a system `ChatMessage` with id
  `lk.agent_task.instructions` (`voice/generation.py:1280`), whose content ends with a `CacheBreakpoint` on each
  turn's working copy. `session.history` does not hold it. Typed turns (`run(user_input=…)`) never call
  `on_user_turn_completed`.
- `fake_job_context` never cleans up `JobContext._tempdir`, so `-W error` shows a teardown `ResourceWarning`; it's
  upstream and harmless.

## C1-05 as built

- `concierge/worker.py`: `server = AgentServer(shutdown_process_timeout=30, setup_fnc=prewarm)`; `prewarm` puts
  `silero.VAD.load()` in `proc.userdata["vad"]` (setup_fnc runs in each job process). `on_request` only accepts
  (C6-04 adds the kill switch). The entrypoint parses the metadata, builds providers from `Settings()` inside the job,
  and awaits `session.start(agent=ConciergeAgent(load_pack()), room=ctx.room, room_options=RoomOptions(
  participant_identity="visitor-<id>", text_input=TextInputOptions(text_input_cb=…)), record=recording_options())`.
  `session.start` connects the room itself (`JobContext.connect()`); C3-02 replaces that with
  `gather(ctx.connect(), preload)`. Run with `python -m concierge.worker start|dev`.
- Turn handling is `{"turn_detection": "vad", "interruption": {"mode": "vad"}}`. Without the interruption mode,
  `voice/agent_activity.py:5232` builds the hosted `AdaptiveInterruptionDetector` in dev/console mode (D7 wants no
  hosted allowance).
- `recording_options()` = `{"audio": record_audio, "redaction": True}`; `init_recording` raises only when audio and
  redaction are on with `transcript: False`, which we never set.
- `concierge/dispatch.py`: `parse_dispatch` raises `DispatchError` (a `ValueError`) for empty, non-JSON,
  non-object, or invalid metadata; messages name fields only, never values. `visitor_id` must be a **lowercase** UUID4
  (not coerced, so `visitor-<id>` matches the page's identity verbatim). Bad metadata: warn, `ctx.shutdown(reason=
  "bad dispatch metadata")`, return before any provider is built.
- `concierge/text_input.py`: `make_text_input_cb(on_text)` calls `on_text(ev)` (exceptions logged without text) and
  then awaits `_default_text_input_cb`. `ChannelTags.on_text` records typed texts (deque, max 32);
  `channel_of(user_text)` matches one and returns `"text"`, else `"voice"`. Nothing calls `channel_of` yet: C4's
  `conversation_item_added` handler does. A real `AgentSession` test confirms the user `ChatMessage.text_content` of a
  typed turn equals `ev.text`, so the match works.

  checks this first, against the source of `voice/run_result.py`.
