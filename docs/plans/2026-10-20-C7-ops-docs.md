## Part 1: the scripts

All Python scripts run as `.venv/bin/python scripts/<name>.py …` from the repo root, like `memory_history.py`.
`concierge` is importable because the package is installed editable. They print results to stdout and errors to stderr.
Exit codes: 0 means it ran and is OK; 1 means it ran and found a problem; 2 means usage error, missing input or missing
key. None of them prints a secret or reads the env file: keys come from the process environment only.

### `scripts/eval_memory.py` (spec §4.9; C7-02 step 1)

```
.venv/bin/python scripts/eval_memory.py [--offline] [--case NAME]... [--dir DIR]
```

- `--dir` defaults to `evals/memory`. Every `*.yaml` in it, in name order, goes through `load_script` and
  `concierge.evals.runner.run_script`. That is the real `Turn` building, `extract()` and `merge()` on a temp `Store`,
  as the offline twin does (`tests/test_memory_evals_offline.py`).
- `--case NAME` (repeatable) runs only the named scripts (`MemoryScript.name`, which matches the file stem). An
  unknown name exits 2.
- **Live (the default).** `settings = Settings()`. The key it needs is `ANTHROPIC_API_KEY` under
  `llm_provider == "anthropic"` (the default) and `OPENROUTER_API_KEY` under `openrouter`. When that variable is unset
  or empty, it prints `<NAME> not set` to stderr and exits **2** before building anything. Otherwise the factory is
  `lambda n: build_llm("extractor", settings)`, the configured provider and model (B1: `claude-sonnet-5-5`, effort
  `low`). `run_script` doesn't close the factory's LLMs, so the factory keeps the ones it builds in a list, and the
  script `aclose`s them after each case. `recorded_ops` are ignored.
- **`--offline`.** The factory is `concierge.testing.replay.Replay(script)`, the recorded `emit_ops` replies, and no
  key is checked. This is the same path as the offline twin, so recall is 100 % and harm is 0. The tests assert that.
- **Output.** A markdown table, one row per case, then a total:

  ```
  | case | recall | harm hits |
  |---|---|---|
  | 01-introduction | 2/2 (100 %) | 0 |
  | 05-injection | n/a | 0 |
  | 13-url-and-secret | 1/1 (100 %) | 1: forbidden interests "https://…" |
  | total | 17/18 (94 %) | 1 |
  ```

  - **Recall** is `(len(expected) - len(missing_expected)) / len(expected)`. A case with no expected facts shows `n/a`
    and isn't counted in the total.
  - **Harm hits** are `ScriptResult.forbidden_hits`, counted and then listed by name, joined with `; `. They include a
    forbidden fact, a duplicate, a `gone` value still valid, and anything stored when `nothing_stored` is set.
- **Exit.** 0 with no harm hits; 1 with any harm hit. A recall below 100 % is reported, not a failure: the live
  extractor can miss things, and the README says so.
- The `extraction_ran` payloads (`tool_called`, `ms`, `prompt_tokens`) aren't printed. A `--verbose` flag is out of
  scope.

### `scripts/latency_report.py` (spec §4.7; C7-02 step 2)

```
.venv/bin/python scripts/latency_report.py <db>
```

- It opens `<db>` read-only (`Store.open_readonly`, as `memory_history.py` does), so it never creates or changes a
  database. A wrong argument count, no such file, or not a memory store exits **2** with a one-line message, never a
  traceback.
- It reads every `anonymous_turn_metrics` row. These rows are numbers only (B9), so the output has no visitor data.
- **Fields, in this order:** `eou_ms`, `stt_ms`, `llm_ttft_ms`, `tts_ttfb_ms`, `total_ms`, `memory_on_turn_path_ms`,
  `preload_ms`, `extraction_ms`. Each field's statistics use only its non-null values: text turns have no STT or
  end-of-turn values, `preload_ms` is set on turn 1 only, and `extraction_ms` only after a merge.
- **Percentiles** use linear interpolation between closest ranks: numpy's default, and
  `statistics.quantiles(values, n=100, method="inclusive")`. The script uses its own 6-line `percentile(values, q)`,
  because `quantiles` needs two points. With one value, p50 = p95 = that value. With none, both cells are `n/a`.
  Values print with one decimal.
- **Cached-token share** is `sum(cached_tokens) / sum(prompt_tokens)` over the rows where both are non-null, as a
  percentage with one decimal. `n=` counts those rows. A zero prompt sum shows `n/a`.
- **Output.** The same table shape as the README's Results section, so Michael pastes it in as is:

  ```
  | field | n | p50 | p95 |
  |---|---|---|---|
  | eou_ms | n=20 | 105.0 | 190.5 |
  | … |
  | cached-token share | n=20 | 81.2 % | |
  ```

  Exit 0, even with no rows: every `n=0` row prints `n/a`, so an empty db still gives a table.

### `scripts/run-worker.sh` (B10; C7-02 step 4)

```
scripts/run-worker.sh [start|dev|console|connect|download-files|--help]   # default: start
```

```bash
#!/usr/bin/env bash
# Start the concierge worker (Michael runs this, or the systemd unit does). Never prints a value.
set -euo pipefail
cd "$(dirname "$(readlink -f "$0")")/.."
f="$HOME/.config/voice-concierge/env"
if [[ -f $f ]]; then set -a; . "$f"; set +a; fi
need=(LIVEKIT_URL LIVEKIT_API_KEY LIVEKIT_API_SECRET)
if [[ ${CONCIERGE_LLM_PROVIDER:-anthropic} == openrouter ]]; then need+=(OPENROUTER_API_KEY); else need+=(ANTHROPIC_API_KEY); fi
if [[ ${CONCIERGE_SPEECH:-inference} == deepgram ]]; then need+=(DEEPGRAM_API_KEY); fi
for name in "${need[@]}"; do
  if [[ -z ${!name:-} ]]; then echo "run-worker: $name is not set (expected in $f)" >&2; exit 1; fi
done
[[ -x .venv/bin/python ]] || { echo "run-worker: no .venv here; run .harness/init.sh first" >&2; exit 1; }
exec .venv/bin/python -m concierge.worker "${@:-start}"
```

- The order matters: the env file, then the check, then `exec`. The first missing name is the one reported. Only names
  are printed, never values.
- The `cd` to the repo root makes `.venv/bin/python` and `-m concierge.worker` work from any cwd, including the
  systemd unit's.
- `"${@:-start}"`: no argument means `start`. `--help` is useful as Stage 0's dry run (below). It prints the worker
  CLI's help and exits 0 without connecting. This was checked here with no keys set: the commands it lists are
  `console`, `start`, `dev`, `connect` and `download-files`.
- Under systemd, `EnvironmentFile=` has already loaded the same file. Sourcing it again is harmless. The env file must
  stay plain `NAME=value` lines (as in `.env.example`), with no `export` and no quoting tricks, so both readers agree.
- **Offline tests never let it reach `exec`**: every test leaves at least one required name unset. Nothing in the
  suite starts a worker.

### How they run (builder's call, in "Decisions")

- They run in-process, in **text mode**, through the real `start_session`. This is the LiveKit test framework's way:
  `livekit.agents.testing.fake_job_context(job_metadata=METADATA, room=FakeRoom())`, a real `AgentSession` and
  `session.run(user_input=…)` (`voice/agent_session.py:855`). They don't join a LiveKit Cloud room, and they need only
  the LLM key. The `LIVEKIT_URL` gate follows spec §7: it marks "Michael's keys are loaded".
- The same seams as `tests/conftest.py`'s `fakes` fixture: `session.build_session` is replaced by
  `AgentSession(llm=build_llm("conversation", settings))`, with no STT/TTS/VAD and the rest of `build_session`'s options
  unchanged. `session.room_start_kwargs` is replaced by `lambda *a: {}`. The extractor and summarizer are the **real**
  `build_llm` ones.
- The store is the temp db from `tests/conftest.py`'s autouse `CONCIERGE_DB_PATH` fixture. A live test never touches
  Michael's real db.
- `concierge.testing.sessions.start` and `shutdown` drive a session to its first reply and then through the shutdown
  callback (the final extraction flush, then the visit summary).
- **Judge.** `RunResult.expect…judge(llm, intent=…)` (`voice/run_result.py:953`) with `build_llm("extractor", settings)`
  as the judge (Sonnet). A judge is used only where a check needs judgment. Store checks are exact.

## Part 3: the systemd user unit (C7-02 step 5)

`deploy/voice-concierge.service`:

```ini
[Unit]
Description=voice-concierge: LiveKit agent worker for the portfolio concierge

[Service]
Type=simple
EnvironmentFile=%h/.config/voice-concierge/env
WorkingDirectory=%h/projects/voice-concierge
ExecStart=%h/projects/voice-concierge/scripts/run-worker.sh start
Restart=on-failure
RestartSec=10
# The first SIGTERM drains live sessions (cli/cli.py:439); a session is at most 10 min (B7), plus 30 s of shutdown work.
TimeoutStopSec=660

[Install]
WantedBy=default.target
```

- `%h` is the user's home in a user unit. The unit assumes the repo is cloned at `~/projects/voice-concierge`, with its
  `.venv` built there. MORNING step 3 says so.
- There's no `After=network-online.target`: a user manager can't order against the system's network target. The worker
  reconnects to LiveKit Cloud by itself.
- A user unit stops when Michael logs out unless lingering is on. MORNING lists `loginctl enable-linger` as optional.
- **Build-only:** the file is written and tested as text. No session runs `systemctl`.

## Decisions (builder's calls; no `D<n>` needed)

- **The live tests run in-process, in text mode**, through the real `start_session`, with the LiveKit test framework
  (`fake_job_context`, `session.run`, `judge`). They don't join a Cloud room. Spec §7 asks for text-mode recall and the
  framework's judge, and the page's real path is covered by Stage 1. The `LIVEKIT_URL` gate stays as spec §7 says.
- **`eval_memory.py` exits 1 on a harm hit, not on a recall miss.** Harm is the anti-goal; a miss is a number to
  report.
- **Percentiles** are linear interpolation (numpy's default). This is stated in the README's Results section, so the
  numbers are reproducible.
- **`TimeoutStopSec=660`**, so `systemctl stop` lets a live session finish (the drain) instead of killing it at
  systemd's default 90 s.
- **`--dir` on `eval_memory.py`** exists for the tests (a temp dir with a script that stores a forbidden fact). Michael
  never needs it.
