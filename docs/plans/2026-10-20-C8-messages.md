# C8: messages for Michael (stretch, spec §4.6)

Short by design: the table (`messages_for_michael`, C2), its erasure (C2-04) and the gate's `purpose="contact"` (C4)
already exist. C8-01 adds the tool that writes the table, a store API, the lister script, and the docs lines. The
same session also binds the health port to 127.0.0.1 (Michael's INBOX answer, 2026-10-20).

## The tool

`ConciergeAgent.leave_message_for_michael(text: str, contact: str | None = None) -> str`, a third
`@llm.function_tool` next to `remember` and `forget`. Its logic is `do_leave_message(writer, text, contact)` in
`concierge/message_tool.py`; the agent method only forwards, like the memory tools.

- The visitor asked, so the tool waits for the write, like `remember` (spec §4.4 "Hot-path writes"): one local SQLite
  write on the writer's store thread (`MemoryWriter.call`), in order with the background runs. Nothing on the
  `conversation_item_added` path changes, so the §4.4 turn-path test still holds.
- The write is `Store.add_message(thread_id, text, contact) -> int`: one `write(thread_id, None, fn)`, i.e. under the
  thread's fence. An erased thread raises `ThreadMissing`, the row is never written and the thread is never
  re-created (erasure wins, §4.2). The tool then sets `writer.erased` and answers `CANT_SAVE`.
- **Caps.** `text` at most 500 characters, `contact` at most 120, both after `strip()`. Over the cap the tool writes
  nothing and tells the model to shorten it (`TOO_LONG`); it never truncates, so Michael never reads half a message.
  An empty or whitespace-only `contact` is stored as NULL.
- **Replies** never echo the text or the contact: `MESSAGE_LEFT`, `TOO_LONG`, `CANT_TAKE`, `CANT_SAVE`,
  `STORE_FAILED`.
- **Session without memory** (`memory=None`, or erased): `CANT_SAVE`, nothing written.

## The gate exception

Spec §4.4: contact details volunteered for `messages_for_michael` are the one exception to the write gate.

- `contact` runs `check_text(contact, purpose="contact")`: the email and phone rules are lifted, every other rule
  (instruction, url, secret, code, unsafe characters) still applies.
- `text` runs `check_text(text)` with the default `purpose="fact"`: contact details belong in `contact`, so an email
  in the text is rejected and the reply says to put it in the contact field.
- A rejection journals `gate_rejected` with `{"field": "text" | "contact", "reason": ...}` and never the value (D8).
- Facts never use `purpose="contact"`: an email in a `name` fact is still rejected as `email`, by the merge and by
  `remember`.

The prompt gets one line: call `leave_message_for_michael` when the visitor wants to leave a message, with a contact
only if they offer one.

## The script

`.venv/bin/python scripts/messages.py <db>` prints one tab-separated line per message, newest first
(`created_at DESC, id DESC`): `created_at` (ISO 8601 UTC, as in `memory_history.py`), the contact or `-`, the text.
It opens the db read-only (`Store.open_readonly`) and reads `Store.messages()` (a list of the pydantic `Message`
model). Exit 2 on usage, a missing file or a file that is not a memory store, like `memory_history.py`. It prints
visitor data, so it is for a terminal on the box that holds the db.

## Erasure

`forget_me` already deletes `messages_for_michael` rows (`_CHILD_TABLES`, plus the cascade). `tests/test_erasure.py`
switches its seed from raw SQL to `Store.add_message` and gains a test that a message left through the tool is gone
after `forget_me` while another visitor's stays.

`worker.py:323`; the HTTP server binds `self._host`, `worker.py:654`). `test_import_needs_no_keys` also asserts
`s._host == "127.0.0.1"`. MORNING.md drops the "keep 8081 closed at the firewall" line and the question; the README
