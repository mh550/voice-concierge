### `MemoryPayload` (topic `concierge.memory`, and the `get_memory` response)

```python
class VisitorView(BaseModel):          # extra="forbid" on all four models
    name: str | None
    visits: int                        # Thread.visits (ge=0)

class FactView(BaseModel):
    id: int                            # facts.id (D13)
    slot: SlotName
    value: str
    channel: Channel                   # "voice" | "text"
    source: Source                     # "user_said" | "user_typed" | "user_asked_to_remember"
    learned_at: str                    # ISO-8601 UTC with "Z", from Fact.created_at (ms)
    confidence: float                  # 0..1

class MemoryPayload(BaseModel):
    visitor: VisitorView
    facts: list[FactView]
    summary: str | None                # VisitorState.last_visit_summary
    updated_at: str                    # ISO-8601 UTC with "Z": the store's clock when the payload was built
```

`build_memory_payload(store, thread_id) -> MemoryPayload` (blocking; called through `writer.call` or
`asyncio.to_thread`) reads, in one locked read, the thread's `visits` and the `ThreadSnapshot` (`state.name`,
`state.last_visit_summary`, the valid facts). No store call gives that today: `thread_for` takes a visitor id
(store.py:85) and `ThreadSnapshot` has no `visits` (models.py:172-177), so C6-02 adds `Store.memory_view(thread_id) ->
tuple[Thread, ThreadSnapshot]` (one `_locked()` block, `ThreadMissing` when the thread is gone; store.py is at 201
lines). Only facts with `valid_to IS NULL` (superseded and invalidated ones are history, not memory;
`scripts/memory_history.py` shows those). `valid_facts` orders by `valid_from, id` (store.py:177), so the payload sorts
explicitly by `(created_at, id)`, oldest first. Then the cap: while
`len(payload.model_dump_json().encode()) > MAX_BODY_BYTES`, drop `facts[0]` (the oldest). Bytes, not characters: a
non-ASCII value is 2–4 bytes a character, so `len(body) > 15 * 1024` (the step's wording) is implied by the byte check.
A missing thread (`ThreadMissing`: erased between the call and the read) returns `empty_memory_payload()`.

`empty_memory_payload() -> MemoryPayload`: `visitor {name: None, visits: 0}`, `facts []`, `summary None`, `updated_at`
now. The forget-me publish and a session without memory use it.

**Size.** The largest real memory: 4 single slots (120 chars) + 2 sets × 8 items (60 chars) = 20 facts, about 300 bytes
each, plus a 500-char summary: about 6.5 KB of ASCII, about 18 KB if every character is a 3-byte one. The trim is the
backstop for that case; a test seeds it (see Tests).

## Part 2: publishing (C6-02)

### `publish(room, topic, payload) -> None`

```python
async def publish(room: rtc.Room, topic: str, payload: BaseModel) -> None:
    body = payload.model_dump_json()
    if len(body.encode()) > MAX_BODY_BYTES:
        raise PayloadTooLarge(topic, len(body.encode()))
    await room.local_participant.send_text(body, topic=topic)
```

`room` is typed as `rtc.Room` but only `room.local_participant.send_text` is used, so the tests' fake room
(`FakeRoom` with a `FakeLocalParticipant` recording `(text, topic)` and the registered RPC handlers, in
`concierge/testing/fake_room.py`, shaped from participant.py:518 and 864) passes. `PayloadTooLarge(ValueError)` names
the topic and the size, never the body (it can hold visitor values).

### `MemoryPublisher` and when `concierge.memory` is sent

- **At session start**: once, after `session.start` returns, `publisher.schedule()` (so the greeting is not
  delayed). The publisher builds the payload with `writer.call(build_memory_payload, store, thread_id)` (the writer's
  executor keeps it behind the `memory_preloaded` write), or uses `empty_memory_payload()` when there's no memory this
  session. **Every** memory send goes through the publisher, the start one included.
- **After every merge**: the writer's `on_merged(result)` (sync, called from the writer's background run,
  memory_writer.py:151-155) calls `publisher.schedule()`, which starts one task that builds the payload through
  `writer.call` and publishes it. Never on the turn path: `on_merged` runs after `extract` and `merge`.
- **After "Forget me"**: `publisher.final(empty_memory_payload())` sends the empty body and sets `closed`.

`MemoryPublisher` holds an `asyncio.Lock` so sends go out in the order they were built, a `closed` flag and its own
task set. `final(payload)` sets `closed` **before** it takes the lock, and every scheduled send re-checks `closed`
under the lock after its build, so a start or merge build already in flight when "Forget me" lands is dropped and the
empty body is the last one the page sees. `aclose()` sets `closed` and cancels pending sends; it runs **first** in
`on_shutdown` (see "Shutdown and the disconnected room").
A send that fails (`StreamError`, the room gone) or a `PayloadTooLarge` is logged by type and dropped: the page asks
again with `get_memory`.

**Order at start.** The page registers its handler before `connect()` (§6), and explicit dispatch creates the agent's
job when the visitor's token connects, so the visitor is in the room before the agent's first send. If not, the
page's `get_memory` covers it (risk below).

### `TurnMetricsCollector(store, session_id, publish)`

```python
class TurnMetricsCollector:
    def __init__(self, store: Store | None, session_id: str, publish: Callable[[MetricsPayload], Awaitable[None]],
                 *, preload_ms: float | None = None, compactions: Callable[[], int] = lambda: 0) -> None: ...
    def on_item_added(self, ev: ConversationItemAddedEvent) -> None: ...      # sync, registered on the session
    def on_llm_metrics(self, m: LLMMetrics) -> None: ...                     # sync, on session.llm "metrics_collected"
    def on_state_changed(self, ev: AgentStateChangedEvent) -> None: ...      # sync: "listening" closes a turn
    def note_extraction(self, ms: float | None) -> None: ...                 # from on_merged
    def stop_publishing(self) -> None: ...                                   # on_shutdown, first: the room is gone
    async def aclose(self) -> None: ...                                      # waits (≤ 5 s) for its store writes
```

- A turn **opens** at a user message, or at an assistant message when none is open (the greeting). A second user
  message before any assistant message replaces the held one (the last one got the reply).
- Assistant messages fill the assistant fields, **first non-null value per key wins**. One user turn can bring two
  assistant messages: with the `remember` / `forget` tools, the text before the tool call is one message
  (agent_activity.py:3925-3936) and the tool reply chain adds another (4084-4104). Both belong to the one turn.
- A turn **closes** on `agent_state_changed` with `new_state == "listening"` once it has an assistant message
  (`collector.on_state_changed`, registered next to the Compactor's), or when the next user message arrives after an
  assistant message. Then `turn = n`, the pending tokens, extraction and compaction flags go on it, `n += 1`, and the
  pending values clear. The greeting is turn 1 (no user fields; it carries `preload_ms`, §6 "first message only"). An
  interrupted reply still closes its turn. At shutdown an open turn with an assistant message is written, not published.
- Only `ChatMessage` items reach `conversation_item_added` (the event's `item` is `ChatMessage | AgentHandoff`,
  events.py:418); `AgentHandoff` is ignored.
- **Tokens**: `on_llm_metrics` skips `LLMMetrics.cancelled` calls. Preemptive generation is on by default
  (`PreemptiveGenerationOptions.enabled`, voice/turn.py:200-205) and `build_session` leaves it on (it cuts latency), so
  a discarded preemptive reply is routine; its stream is cancelled, so skipping `cancelled` keeps it out of the turn.
  A preemptive call that finished before it was discarded still counts (Risks).
- The handlers do **no I/O**: closing a turn builds the `MetricsPayload` and starts two tasks (its own sets): the
  store write `asyncio.to_thread(store.add_turn_metrics, session_id, payload)` (skipped when `store` is None) and
  `publish(payload)` (skipped after `stop_publishing`). A failure in either is logged by type; the other still runs.
  `aclose()` cancels pending publishes and waits at most 5 s for the store writes. `tests/test_critical_path.py` (+)
  asserts the handler awaits nothing (the same static check the writer's handler has).
- `session_id` is the session's `uuid.uuid4().hex`, which `add_turn_metrics` already requires (store_base.py:185).
  No visitor id, no text: the table has neither column (schema.py:74-89).

Registered in `session.py` after the Compactor's handler: `session.on("conversation_item_added",
collector.on_item_added)` and, when `isinstance(session.llm, llm.LLM)`, `session.llm.on("metrics_collected",
collector.on_llm_metrics)`. The writer's `on_merged` is one function in `session.py` that calls
`collector.note_extraction(result.extraction_ms)` and `publisher.schedule()`. `compactions=lambda: compactor.applied`.
The collector runs with or without memory (the anonymous table needs no thread); without a store nothing is written.

## Part 4: the RPCs (C6-04)

### `register_rpcs(room, handlers) -> None`

```python
@dataclass(frozen=True)
class RpcHandlers:
    visitor_identity: str                              # f"visitor-{visitor_id}"
    erase: Callable[[], Awaitable[None]]               # cancel pending memory work, then store.forget_me
    memory: Callable[[], Awaitable[MemoryPayload]]     # build_memory_payload, or the empty one
    publish_memory: Callable[[MemoryPayload], Awaitable[None]]   # MemoryPublisher.final
    end: Callable[[str, str], Awaitable[None]]         # say_and_end(session, line, shutdown, reason)
    tasks: set[asyncio.Task[Any]]                      # the session's tasks: on_shutdown waits for them
```

`register_rpcs` calls `room.local_participant.register_rpc_method(FORGET_ME_METHOD, on_forget_me)` and
`(GET_MEMORY_METHOD, on_get_memory)`.

- **Caller check.** Both handlers raise `RpcError(4403, "not this visitor")` unless `data.caller_identity ==
  handlers.visitor_identity`. One room per visit holds only the visitor and the agent; the check keeps any other
  participant (a second agent, a misrouted dispatch) from erasing or reading the memory. The payload is ignored.
- **`concierge.forget_me`** returns `json.dumps({"ok": True})` (`'{"ok": true}'`) **before** any erase work: it starts
  one task with `track(handlers.tasks, _forget(handlers))` and returns. A second call while that task runs returns the
  same answer and starts nothing. `_forget`:
  1. `await handlers.erase()`: `forget_visitor(writer, visitor_id)` (erasure_hooks.py:30-34: `cancel_pending` first,
     so the writer's `erased` is set and the Compactor is cancelled, then `store.forget_me` on the writer's thread).
     Without a writer (no memory this session), `asyncio.to_thread(store.forget_me, visitor_id)`; without a store,
     nothing. A `StoreError` from a closed writer (C4 review B-M4) falls back to `asyncio.to_thread(store.forget_me)`.
  2. `await handlers.publish_memory(empty_memory_payload())`: facts `[]`, visitor `{name: null, visits: 0}`; the
     publisher closes, so no later merge publish can follow it.
  3. `await handlers.end(GOODBYE_LINE, "forget_me")`.
  An error in 1 is logged by type and still runs 2 and 3 (the page already showed "forgotten"; a failed erase is
  journaled nowhere, since the thread may be half gone, and logged).
- **`concierge.get_memory`** returns `(await handlers.memory()).model_dump_json()`: the same JSON as the topic, under
  the same 15 KiB cap. With a writer it builds through `writer.call`; with a store but no writer (the preload missed
  its deadline) it builds through `asyncio.to_thread` from `store.thread_for(visitor_id)`, read-only; only with no store
  or no thread is it the empty payload.

**Erasure and the shutdown (C5 review A-M3).** The forget task is in the session's `tasks`, so `on_shutdown`'s first
step (`gather(*tasks)`) waits for it; `writer.erased` is then set, so the flush and the summary are skipped (they
already check it). RPCs stop with the room's disconnect, which comes before the
shutdown callbacks, so no forget request lands while the writer or the store closes (see "Shutdown and the
disconnected room").

### `concierge/limits.py`

```python

    """After max_s (Settings.session_max_s = 600), say_and_end(session, TIME_UP_LINE, end, "time limit")."""

def utc_day(now_ms: int) -> str: ...                       # "YYYY-MM-DD", UTC

    """Count this session (store.count_session in a thread) and return count > cap. cap is

    capped: one line, then ctx.shutdown."""

    """over_daily_cap, then on True say_and_end(session, DAILY_CAP_LINE, end, "daily cap"). True when capped."""
```

`add_to_chat_ctx=False` keeps the three lines out of the history, so the writer never journals or extracts them (and
after an erase there is no thread to journal to). The lines are not about Michael, so no knowledge-pack rule applies.

**The timer** logs its failures by type (a done callback, like `track`'s) and is not in the session's `tasks` (`on_shutdown` gathers those first, and a sleeping 10-minute task would
eat its 25 s deadline): `start_session` keeps it on `Started.timer`, and `on_shutdown` cancels it before anything else.

**The daily cap and the preload.** B7 counts per visitor per UTC day (`count_session`, store_erasure.py:88-101; the
hashed key survives `forget_me`). The count must come before the preload ("closes without preloading memory") and the
preload overlaps `ctx.connect()` (§4.3, `test_entrypoint_connects_and_preloads_concurrently`). So `session.py` does the
two halves at the two points they belong:

1. The count is **its own tracked task**, `counting = track(tasks, over_daily_cap(store, visitor_id, cap))`, started
   first (one `BEGIN IMMEDIATE` upsert, about 1 ms). The preload task awaits it and returns `CAPPED` instead of reading
   the thread when it's over. Both run concurrently with `ctx.connect()`. The count is not under the preload's 1 s
   deadline (session.py:42, 102-105): if the preload misses it, `session.py` still awaits `counting` (at most 5 s, the
   store's busy timeout) after `session.start` and before the greeting, and ends the session when it's over the cap.
   So the cap fails closed under contention. A count that raises (a store error) is logged and lets the session run
   memoryless, as a failed store does today.
2. On `CAPPED`: no writer, no Compactor, no collector; the RPCs are registered (a capped visitor can still press
   "Forget me"; `erase` goes through `asyncio.to_thread(store.forget_me)`, `memory` returns the empty payload),
   `session.start` with the memoryless agent, no greeting, then `say_and_end(session, DAILY_CAP_LINE, ctx.shutdown,
   "daily cap")`.

`enforce_daily_cap` is both halves in one call, for a caller that already has a running session; it's what the step
names and what `tests/test_limits.py` drives. `session.py` uses `over_daily_cap` and `say_and_end` directly so the count
stays ahead of the preload. (Proposed change below: name the two halves in C6-04's step.)

With no store (it failed to open) there is no count and no cap: the session runs memoryless, as today.

### `start_session` after C6 (the order)

1. `info`, `session_id`; `on_shutdown` registered first (as today).
2. The count task and the preload task (`count → preload`; neither when the store is missing), gathered with
   `ctx.connect()`.
3. `build_session`; writer, Compactor and collector as today plus the collector; `register_rpcs(ctx.room, handlers)`
   (after connect: `local_participant` exists).
4. `session.start(...)`; on `CAPPED` (from the preload, or from `counting` when the preload missed its deadline) go to
   the cap line and return `Started` with `greeting=None` (`Started.greeting` becomes `SpeechHandle | None`).
5. The greeting; `session_started` journaled (tracked, as today); the start `concierge.memory` publish (tracked);
   `Started.timer = start_session_timer(session, settings.session_max_s, ctx.shutdown)`.

### Shutdown and the disconnected room

The job disconnects the room **before** it runs the shutdown callbacks (`await self._room.disconnect()` at
ipc/job_proc_lazy_main.py:478-479, the callbacks at 497). So nothing sent from `on_shutdown` reaches the page, and a
`send_text` there could wait on a callback that never comes (participant.py:885-893). `on_shutdown` gains, in order:

1. Cancel `timer`; `publisher.aclose()` (closed, pending sends cancelled); `collector.stop_publishing()`. Before
   anything else, so the flush's `on_merged`, the last turn and a forget task in flight publish nothing.
2. As today: `gather(*tasks)` (which now includes a forget task in flight: its erase still runs, its final publish is
   a no-op, its `say_and_end` ends at once on the closing session and `ctx.shutdown` is idempotent,
   job_proc_lazy_main.py:298-305), the compaction, the flush, the summary, `session_ended`.
3. In the `finally`, `collector.aclose()` (≤ 5 s for its store writes) before the writer and the store close.

RPCs can't arrive once the room is disconnected, so no "Forget me" lands after step 1.

## Risks

- **First send before the page subscribes.** If the agent's start publish beats the page's handler, the page misses it;
  it can call `get_memory`. The page spec registers before `connect()`, so this needs a page bug.
- **A "Forget me" whose erase is still running when the session ends** is waited for by `on_shutdown`'s
  `gather(*tasks)`, within its 25 s deadline; past that it is logged, and the next visit's "Forget me" erases.
- **A preemptive generation that finished before it was discarded** is not `cancelled`, so its tokens join the next
  turn. Accepted: the per-turn token count is an upper bound; the latency report says so. Turning preemptive
  generation off would fix it at a latency cost; not done.
- **The "listening" close assumes the agent doesn't pass through `listening` between a tool call and its reply.** If
  it does, a tool turn becomes two rows (the second with null user fields). `test_a_tool_call_turn_is_one_row` runs a
  real `AgentSession` with a tool call to pin it.
- **A second user message before a reply** (an interruption) drops the first one's user metrics. Accepted: the reply
  answers the last one.
- **Speaking the limit lines when the TTS is down:** `say_and_end` ends after `SAY_TIMEOUT_S` regardless.

## C6-03 build notes

- **Pause on interruption** (on by default, `resume_false_interruption`, voice/turn.py:195) sets `listening` while a
  reply is only paused (agent_activity.py:2390), and a reply interrupted while paused gets no later `listening`
  (:3946). So a turn closes on `listening` only when an assistant message arrived since the agent last entered
  `speaking`, and an `interrupted` assistant message that lands while the agent is listening closes its turn at once.
  Tests: `test_a_paused_reply_that_resumes_is_one_turn`, `test_an_interrupted_reply_closes_when_its_message_lands`,
  `test_a_pause_during_a_tool_reply_is_not_a_turn` (Opus review of C6-03, I1 and I2).
- **Residual risk:** a preemptive call for the next reply that finishes before the interrupted message lands puts its
  tokens on the interrupted turn. `LLMMetrics.speech_id` is never set by `LLMStream` in 1.8.8, so no id ties a call to
  a reply. The `cancelled` skip only drops streams cut off before their usage chunk.
- **`anonymous_turn_metrics.created_at`** (the step's column list): ms rounded down to the minute (B9: harder to line up
  with other telemetry). `SCHEMA_VERSION` 1 → 2 with `schema.MIGRATIONS[2]` adding the column to a v1 file
