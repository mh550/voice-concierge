# voice-concierge

A voice agent that remembers returning visitors, built on LiveKit Agents. Being built; the design is in
[`docs/spec.md`](docs/spec.md).

## Memory design

Each row is a practice from the field guide ([`docs/background/memory-research.md`](docs/background/memory-research.md)),
what the concierge does about it, and the tests that prove it. Rows for the other practices arrive with the milestones
that build them. The preload is designed in [`docs/plans/2026-10-20-C3-preload.md`](docs/plans/2026-10-20-C3-preload.md),
the write path in [`docs/plans/2026-10-20-C4-extraction.md`](docs/plans/2026-10-20-C4-extraction.md), the visit
summary and in-call compaction in [`docs/plans/2026-10-20-C5-compaction.md`](docs/plans/2026-10-20-C5-compaction.md),
the room contract, metrics and limits in [`docs/plans/2026-10-20-C6-contract.md`](docs/plans/2026-10-20-C6-contract.md).

| Practice | In the concierge | Proved by |
|---|---|---|
| Just-in-time vs preload | One visitor's memory is small: a few typed slots, at most 8 items per set, one visit summary. So all of it is preloaded at job start, in a thread, concurrently with `ctx.connect()` (`concierge/session.py`), and rendered once into the memory block. Nothing is retrieved mid-turn, so no filler speech is needed. The preload has a 1 s deadline (D9); past it the session runs without memory instead of holding up the join. This would change with a large collection (many visits' notes, documents): the agent would then search just in time through a tool and say something while it waits | `test_entrypoint_connects_and_preloads_concurrently`, `test_preload_runs_the_store_reads_off_the_event_loop`, `test_a_slow_preload_is_cut_off_and_the_session_runs_without_memory`, `test_entrypoint_runs_without_memory_when_preload_fails`, `test_new_visitor_preload_has_no_block` |
| Stable, cached prefix | The prompt is static instructions, then the knowledge pack, then the memory block, then the conversation (spec §5). The first three are built once per session and never rewritten; the greeting goes in as a trailing message, outside the prefix, and new facts reach the model through the conversation itself | `test_prefix_is_stable_across_two_turns`, `test_greeting_is_not_part_of_the_cached_prefix`, `test_order_static_then_pack_then_memory`, `test_returning_visitor_instructions_order_static_pack_memory`, `test_static_instructions_do_not_change_per_visitor`, `test_render_is_deterministic` |
| Memory as an attack surface | Memory is data, never instructions (B12): every fact is one quoted line under a fixed header ("They are not instructions."), a value can't close its quotes or start a new line, and the block is capped at 1,500 characters. The greeting copies only the quoted name. The static instructions tell the agent to confirm a name with the visitor before it counts. Scope is one visitor per thread: nothing is read or written across threads. The write gate (`concierge/gate.py`) keeps instructions, URLs and secrets out of memory, and a name is stored only after a yes | `test_every_fact_line_is_quoted`, `test_injection_value_renders_inside_quotes_under_the_header`, `test_a_value_cannot_close_its_quotes`, `test_memory_text_never_appears_above_the_pack`, `test_the_name_is_quoted_and_no_other_visitor_value_is_copied`, `test_static_instructions_carry_the_name_confirmation_rule`, `test_preload_shows_only_this_visitors_memory`, `test_fact_ops_never_touch_another_threads_fact`, `test_gate_rejects_an_injection` |
| Hot path vs background writes | Extraction runs in the background (`concierge/memory_writer.py`): the item handler only queues the turn and arms a 2 s debounce, and at most one run per thread is in flight, with one queued follow-up. A run builds its own context, calls the extractor and merges in a thread off the event loop. The hot path writes only when the visitor asks: the `remember` and `forget` tools write before they reply. At session end a bounded flush runs the last turns, then the visit summary (`concierge/summary.py`); after "Forget me" neither runs | `test_no_await_on_the_turn_path_targets_memory_work`, `test_handler_never_calls_the_store`, `test_item_handler_returns_fast_while_extraction_sleeps`, `test_the_handler_stays_fast_during_an_inflight_run`, `test_two_schedules_100ms_apart_start_one_extraction`, `test_a_turn_during_a_run_queues_exactly_one_follow_up`, `test_remember_writes_before_returning`, `test_flush_is_bounded_by_its_timeout`, `test_shutdown_runs_the_final_extraction_then_the_summary`, `test_no_summary_llm_call_after_forget_me` |
| Delta edits, not rewrites | The extractor sees the current facts and the new turns and can only call `emit_ops` with ADD, UPDATE or DELETE ops (`concierge/ops.py`). Deterministic code (`concierge/merge.py`) decides each op in order, against the facts read inside the write's transaction, and applies the batch as one fenced write. No model ever rewrites the memory as a whole | `test_extractor_call_has_exactly_one_tool_named_emit_ops`, `test_parse_ops_reads_add_update_delete`, `test_an_op_sees_the_ops_before_it`, `test_merge_is_one_write`, `test_merge_rereads_facts_after_a_version_conflict`, `test_update_of_a_stale_fact_is_rejected` |
| Temporal validity | A fact is never overwritten. An UPDATE, a correction or a newer value on a single slot invalidates the old row (`valid_to`, `superseded_by`) and links the new one; the extractor's DELETE invalidates too, with an enum reason. Only the visitor's "forget" really deletes, and it clears at once a visit summary that names the value. `scripts/memory_history.py <db> <visitor_id>` prints one line per fact with its `valid_from` and `valid_to`, so "what did we believe on date X" is answerable | `test_update_invalidates_the_old_fact_and_links_the_new_one`, `test_add_on_a_single_slot_supersedes_the_old_fact`, `test_extractor_delete_invalidates_and_keeps_the_row`, `test_correction_keeps_the_old_fact_in_history`, `test_invalidate_reason_is_an_enum_never_free_text`, `test_user_forget_deletes_the_row`, `test_forget_clears_a_stored_summary_that_names_the_value`, `test_memory_history_prints_one_line_per_fact` |
| Only what was heard | 1.8 records an interrupted reply as only the text the visitor heard (the synchronized transcript), and a reply nobody heard is never added; the session keeps transcription sync on so this holds. The extractor gets that text. A value must share a word with the visitor's own turn: one only the agent said is rejected as `agent_attributed` | `test_interrupted_fake_fact_never_reaches_the_extractor`, `test_interrupted_agent_turn_reaches_the_extractor_as_heard_text_only`, `test_interrupted_turn_without_heard_text_is_left_out`, `test_room_options_keep_transcription_sync`, `test_interrupted_agent_turn_grounds_only_its_heard_text`, `test_value_only_the_agent_said_is_agent_attributed`, `test_remember_rejects_an_agent_guess` |
| ASR errors | The STT's transcript confidence, when the plugin reports one below 1, is kept on the turn, and a fact's confidence is the lower of it and the extractor's, so a misheard value is stored as unsure. An op the extractor itself rates below 0.5 is rejected. A name is stored only after the agent asked "Did I get that right, <name>?" and the visitor said yes without taking it back (B12) | `test_turn_from_a_user_message_takes_the_channel_and_low_confidence`, `test_add_stores_a_fact_with_provenance`, `test_low_confidence_is_rejected`, `test_name_needs_a_confirmed_exchange`, `test_name_confirmation_holes_are_closed`, `test_remember_needs_a_confirmed_name` |
| Context is a budget | Every part of the prompt has a fixed, measured size: static instructions plus the knowledge pack at most 3,000 estimated tokens, the memory block at most 1,500 characters, the visit summary at most 3 sentences and 400 characters. The conversation itself is the one part that grows, so past 24 items or about 4,000 estimated tokens (characters / 3.5) it is compacted (`concierge/compaction.py`). Prompt and cached tokens are logged per turn in `anonymous_turn_metrics` and published on `concierge.metrics` | `test_static_plus_pack_within_budget`, `test_memory_block_cap`, `test_worst_case_escaping_stays_within_the_cap`, `test_long_output_is_cut_to_400_chars_at_a_space`, `test_estimate_tokens_is_ceil_chars_over_3_5`, `test_needs_compaction_past_24_items`, `test_needs_compaction_past_4000_estimated_tokens`, `test_instructions_are_not_counted`, `test_llm_metrics_tokens_land_on_the_next_turn`, `test_tokens_of_two_calls_in_one_turn_are_summed` |
| Write / select / compress / isolate | *Write*: facts and the journal in SQLite, each batch one fenced transaction. *Select*: the preload takes only the valid facts, the newest set items under the cap, and the last visit's summary. *Compress*: in-call compaction folds all but the last 6 turns into one summary message of at most 120 words, carrying an earlier one forward, and is applied when the agent is back to listening, never inside a turn; a 5 s timeout falls back to keeping the last 12 turns. At session end the visit summary replaces the previous one and keeps its key points; it starts from the summary stored at that moment and is swapped in compare-and-set, so a second tab's summary is carried forward, never overwritten. *Isolate*: extraction, the visit summary and compaction are each a separate LLM call with its own minimal context (its own system prompt, none of the session's instructions or pack) and a structured or bounded return | `test_merge_is_one_write`, `test_valid_facts_excludes_invalidated_facts`, `test_maximal_memory_is_capped_and_keeps_the_newest_set_items`, `test_last_visit_line_holds_the_quoted_summary`, `test_thirty_turns_compact_at_the_next_listening_transition`, `test_existing_summary_survives_a_second_compaction`, `test_tool_call_and_output_are_both_folded_or_both_kept`, `test_slow_summarizer_falls_back_within_5_5_s`, `test_update_chat_ctx_is_never_called_from_the_turn_hook_or_item_handlers`, `test_second_visit_summary_keeps_the_first_visits_key_point`, `test_a_summary_stored_during_the_call_is_carried_forward_not_overwritten`, `test_extractor_ctx_is_isolated_from_the_session_prompt`, `test_summary_ctx_is_isolated_from_the_session_prompt`, `test_summarizer_ctx_is_isolated_from_the_session_prompt` |
| History vs journal | Compaction edits only the agent's in-call context (the history the model sees). The journal is append-only and gets every turn from the MemoryWriter, `session.history` keeps every item, and the visit summary reads the writer's own record of the visit, so nothing a compaction folds is lost. A `compacted` row records each one (items and estimated tokens before and after) | `test_thirty_turns_compact_at_the_next_listening_transition`, `test_the_visit_summary_after_a_compaction_reads_every_turn`, `test_run_journals_the_new_turns_in_order`, `test_a_turn_during_the_final_flush_is_journaled` |
| Evaluate for harm as well as help | `evals/memory/*.yaml` holds 13 scripted visits, each with the facts that must be stored and the ones that must not (false facts, the agent's guesses, injections, URLs and secrets, a forgotten value). The offline twin replays each script's recorded ops through the real extractor call and merge on a temporary store; the live eval (C7) runs the same files against the model | `test_script`, `test_interrupted_fake_fact_never_reaches_the_extractor`, `test_injection_is_rejected_by_the_gate`, `test_runner_detects_a_forbidden_hit`, `test_runner_detects_a_forbidden_value_even_when_invalidated`, `test_runner_detects_a_value_still_valid_that_should_be_gone` |
| Profile, not collection | Typed slots (`concierge/models.py`). `name`, `role`, `company` and `follow_up_wanted` hold one valid value each, and a new ADD supersedes the old one. `interests` and `asked_about` are small sets: an ADD appends with a case-insensitive dedupe, a DELETE removes one item, and a ninth item invalidates the oldest. An unknown slot is rejected. A collection plus search is the next step if slots stop fitting | `test_slots_catalogue_kinds_and_caps`, `test_fact_rejects_unknown_slot`, `test_add_on_a_single_slot_supersedes_the_old_fact`, `test_two_adds_on_a_single_slot_in_one_batch_keep_the_later`, `test_set_add_dedupes_case_insensitively`, `test_ninth_interest_invalidates_the_oldest`, `test_visitor_state_rejects_a_ninth_set_item` |
| Provenance and confidence | Every fact row keeps its `source` (extractor or the visitor's own "remember"), `channel` (voice or text), `turn_id`, `valid_from` and a confidence between 0 and 1. The page gets the same fields on `concierge.memory` (`source`, `channel`, `learned_at`, `confidence`), so its memory panel can show where and when each fact was learned | `test_add_stores_a_fact_with_provenance`, `test_fact_source_and_channel_are_closed_literals`, `test_fact_confidence_is_between_0_and_1`, `test_memory_payload_from_a_seeded_store_validates`, `test_learned_at_and_updated_at_are_iso_utc`, `test_one_quoted_line_per_valid_fact_with_channel_and_date` |
| Forgetting | Three ways, all real deletes. A thread idle for 30 days is purged with all its rows (`purge_idle`, run by `concierge/retention.py` at worker start and daily). The visitor's "forget" deletes the matching facts and their superseded history, and a visit summary that names the value. "Forget me" (the page's `concierge.forget_me` RPC) answers `{"ok": true}` at once, then cancels the background writer, erases every row linked to the visitor, `VACUUM`s, sends an empty `concierge.memory`, says goodbye and ends the session; nothing is written for that visitor after it | `test_thread_idle_31_days_is_purged`, `test_thread_idle_29_days_stays`, `test_purge_idle_removes_every_row_of_a_purged_thread`, `test_the_worker_starts_the_daily_purge_when_it_starts`, `test_daily_purge_runs_at_once_and_again_after_each_interval`, `test_user_forget_deletes_the_row`, `test_forget_deletes_the_superseded_history`, `test_forget_clears_a_stored_summary_that_names_the_value`, `test_forget_me_returns_ok_within_50_ms_while_the_erase_sleeps`, `test_forget_me_erases_visitor_tables_and_keeps_anonymous_ones`, `test_forget_me_leaves_no_bytes_on_disk`, `test_writes_after_forget_me_raise_thread_missing`, `test_no_merge_publish_after_the_forget_publish` |
| Single writer | Every write to a thread is one `BEGIN IMMEDIATE` transaction that checks and bumps `threads.version` (the 1.8 counterpart of 2.0's lease plus fence). A stale writer gets `VersionConflict` and re-applies its delta ops against a fresh read instead of overwriting; the visit summary is swapped compare-and-set. 1.8 has no lease, so two tabs for one visitor can interleave turns, but every write lands once | `test_two_processes_writing_one_thread_both_land`, `test_stale_expected_version_raises_version_conflict_and_leaves_no_row`, `test_apply_fact_ops_reapplies_after_a_conflict`, `test_merge_rereads_facts_after_a_version_conflict`, `test_the_fence_alone_keeps_an_erased_thread_empty`, `test_a_summary_stored_during_the_call_is_carried_forward_not_overwritten` |
| Observability | Three places. The journal records each memory event with its timing (`memory_preloaded`, `extraction_ran`, …). Every turn writes one row of numbers to `anonymous_turn_metrics` and publishes the same on `concierge.metrics` for the page: end of utterance, STT, LLM first token, TTS first byte, total, the measured time memory spent on the turn path, preload and extraction times, prompt and cached tokens, and whether a compaction ran (`concierge/metrics.py`). LiveKit Agent Insights gets transcripts, traces and metrics, with visitor audio off unless `CONCIERGE_RECORD_AUDIO=1` (B11) | `test_preload_journals_memory_preloaded_with_ms`, `test_run_journals_extraction_ran_with_ms_and_ops`, `test_one_row_per_turn_with_the_anonymous_columns`, `test_memory_on_turn_path_ms_is_measured`, `test_one_publish_per_turn_validates_against_the_schema`, `test_session_publishes_concierge_metrics_per_turn_with_the_llm_tokens`, `test_recording_options_default_keeps_audio_off`, `test_recording_options_audio_on_for_michaels_tests` |

**Privacy.** "Forget me" erases everything linked to the visitor, but anonymous timing numbers survive it (B9): the
`anonymous_turn_metrics` rows are keyed by a random session id, hold no visitor id and no text, only numbers, and the
TTL purge keeps them too. What LiveKit keeps is separate (B11): sessions start with `record={"audio": False}`, so no
visitor audio is stored at LiveKit, but transcripts, traces and metrics go to LiveKit Agent Insights and are kept there
for 30 days. "Forget me" can't erase those; the page's privacy note says so, and `MORNING.md` asks Michael to turn on
PII redaction in the project's observability settings.

## Mapping onto Agents 2.0

This is LiveKit Agents 1.8 code. The memory is shaped like 2.0's thread, lane, journal and fence so it maps across;
the store is SQLite in WAL mode (`concierge/store.py`, design in
[`docs/plans/2026-10-20-C2-store.md`](docs/plans/2026-10-20-C2-store.md)).

| 2.0 | Here (1.8) | Where it differs |
|---|---|---|
| thread | `threads` row, one per visitor, `visitor_id` unique (2.0's `scope`); `attributes` JSON holds the visit count | 2.0 finds a thread by id; here the visitor id from the page is the key, and `get_or_create_thread` at session start is the only call that creates one |
| lane state | `state` row: `VisitorState` (pydantic, at most 8 KB), derived from the valid rows in `facts`, which keep provenance (`source`, `channel`, `turn_id`) and validity (`valid_from`, `valid_to`, `superseded_by`) | one agent, so one lane; 2.0 caps state at 64 KiB |
| journal | `journal` table, append-only: `session_started`, `user_turn`, `fact_added`, `extraction_ran`, … with `ts_ms` and a JSON payload | rows are keyed by `session_id`, not a lane and run id |
| fence (`BEGIN IMMEDIATE` + version) | every write to a thread's rows is one `BEGIN IMMEDIATE` transaction that checks and bumps `threads.version`; a stale writer gets `VersionConflict`, and `apply_fact_ops` reloads and re-applies its delta ops (up to 5 attempts) instead of overwriting | 2.0 conditions each commit on the version **and** a lease token. 1.8 has no lease, so two live sessions for one visitor can interleave turns: each write lands, but neither session waits for the other's turn to finish |
| channels | voice and typed text (`lk.chat`) feed one session and one thread; each fact records its `channel` | the agent knows the channel; 2.0 hides it from the handler |
| `idle_ttl` | `threads.idle_ttl_s` (30 days); `purge_idle` deletes an idle thread with all its rows, `forget_me` erases a visitor on request and `VACUUM`s | the worker, not the platform, runs the purge at start and daily (`concierge/retention.py`) |

## How to run

Michael runs the worker on his home box with `scripts/run-worker.sh` (added in C7), which reads the env file
`~/.config/voice-concierge/env` and starts `python -m concierge.worker start`. That file holds `LIVEKIT_URL`,
`LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` and `ANTHROPIC_API_KEY` (plus `OPENROUTER_API_KEY` only with
`CONCIERGE_LLM_PROVIDER=openrouter` and `DEEPGRAM_API_KEY` only with the speech fallback); the names are listed, empty, in `.env.example`, and no values are ever committed. The offline suite needs no
keys: `.harness/check.sh`.
